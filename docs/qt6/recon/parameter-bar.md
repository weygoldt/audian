## bar-structure

The parameter bar is three things: `ParameterGroup` (a framed QGridLayout of label+field rows), `ParameterTabs` (a QToolButton strip over a QStackedLayout), and three builder functions that fill them. `DataBrowser.setup_parameter_bar` (/home/weygoldt/wrk/tools/claudian/.claude/worktrees/qt6-migration/src/audian/databrowser.py:2326-2712) creates `self.parambar` as a plain QWidget with a QGridLayout that holds exactly ONE cell — `grid.addWidget(self.param_tabs, 0, 0)` at :2706 with `setColumnStretch(0, 1)` at :2707 — so the bar's own grid is a trivial wrapper around `ParameterTabs`; margins are `(S8, S8, S8, S6)` = (8,8,8,6) at :2356 and the bar is `(Preferred, Fixed)` at :2352. It is appended LAST to `self.vbox` (:2063, after the splitter added at :2226), which is the only thing making it "the bottom bar". Inside, `ParameterTabs` (:411-580) is a QVBoxLayout of a fixed-height (CHIP_HEIGHT=22) horizontal strip of checkable QToolButtons in an exclusive QButtonGroup (:483-508), then a host QWidget carrying a `QStackedLayout` (:470-478), both pinned `(Preferred, Fixed)` vertically; the current tab is changed by `show_index`/`show_group` driving `stack.setCurrentIndex`, and `stack.currentChanged` -> `_changed` re-checks the button and emits `sigTabChanged(title)` (:517-527). Six group builders exist: Filter, Spectrogram, Envelope, Audio (all in `setup_parameter_bar`), plus `setup_annotation_group` (:5629, "Fixed labels") and `setup_label_group` (:4567, "Editable labels"). Filter/Spectrogram/Envelope are conditional on `"filtered"/"spectrogram"/"envelope" in self.data` (:2367, :2448, :2563); the Heterodyne ROW is conditional on `self.data.rate > 50000` (:2684); the Pair row is hidden unless the audio source is AUDIO_PAIR (:2655, :8412). `equalize` (:371-407) releases the previous `setFixedHeight`, activates every nested layout, takes the max `grid.totalSizeHint().height()` over all groups, sets `setRowStretch(group.rows, 1)` so slack lands below the last row, and gives every `group.body` that fixed height. WIDTH IS THE MIGRATION PROBLEM. Measured offscreen (1200x900, 4 ch, 96 kHz, both panels): bar height exactly 168 px = 8 (grid top) + 22 (tab strip) + 2 (S2) + 130 (stack) + 6 (grid bottom); group minimum widths are Filter 283, Spectrogram 515, Audio 302 (315 with the Pair row shown), Fixed labels 407 empty / 777 with a bundle loaded, Editable labels 265; the TAB STRIP alone has a 489 px minimum (five buttons 64+117+63+108+129 + 4×S2, non-wrapping). A group's minimum obeys `16 (2×S8) + 6×(cols−1) + Σ column minima`, where a column minimum is the max over VISIBLE widgets. Nothing in the bar wraps or scrolls: the only reflowing widget in the whole bar is `CategoryStrip` (/home/weygoldt/wrk/tools/claudian/.claude/worktrees/qt6-migration/src/audian/labeloverlay.py:1244), which hand-packs chips over 2 fixed lines and folds the overflow into a `+N` menu. In a ~300 px dock, the tab strip (489), the Fixed-labels chip rows (696 and 555 px of QToolButtons in plain non-wrapping QHBoxLayouts), the annotation Show row (326), the ColorMapCombo (267, from its hard-coded 64×12 gradient icon), the caption column (up to 114 px for "HIGH-PASS  H / ⇧H") and `LogSlider.setMinimumWidth(AXIS_LEFT_WIDTH*2)` = 112 px (:598) all break.

- **add_row in full: caption always goes in column 0, the i-th field goes in column 1+i, and each field's column may steal the stretch**
  `/home/weygoldt/wrk/tools/claudian/.claude/worktrees/qt6-migration/src/audian/databrowser.py:332-348`
  ```python
def add_row(self, label: str, shortcut: str, *widgets: QWidget) -> list:
    caption = caption_label(label, shortcut)
    if shortcut:
        self.shortcuts.append((label, shortcut))
    self.grid.addWidget(caption, self.rows, 0)
    for i, w in enumerate(widgets):
        self.grid.addWidget(w, self.rows, 1 + i)
        self.claim_stretch(1 + i, w)
    self.rows += 1
    return [caption, *widgets]
```
So a row is: col 0 = a small-caps QLabel reading "NAME  SHORTCUT" (uppercased, font_ui(SIZE_SMALL_PT), tinted fg.muted, built by caption_label at :217-233), cols 1..N = the fields in argument order. - **equalize() gives every group's body the same FIXED height (max over groups of grid.totalSizeHint().height()) and packs the rows at the top**
  `/home/weygoldt/wrk/tools/claudian/.claude/worktrees/qt6-migration/src/audian/databrowser.py:371-407`
  Order matters and is documented: (1) `body.setMinimumHeight(0)` + `setMaximumHeight(UNBOUNDED=16777215)` to release a previous setFixedHeight, or a group can only ever shrink; (2) for EVERY nested layout under body (`body.findChildren(QLayout)`) invalidate()+activate(), because a container field (the chip strip) reports a stale height otherwise; (3) `group.grid.invalidate(); group.grid.activate()`; (4) `height = max(g.grid.totalSizeHint().height() for g in groups)`; (5) per group `grid.setRowStretch(group.rows, 1)` — the empty row past the last one absorbs the slack so rows do not spread apart — and `body.setFixedHeight(height)`.
- **Without equalize the extra height inside a stack cell is distributed BETWEEN rows, not below them, and a group whose contents grew is clipped**
  `/home/weygoldt/wrk/tools/claudian/.claude/worktrees/qt6-migration/src/audian/databrowser.py:372-386`
  Measured now: grid.totalSizeHint().height() is Filter 110, Spectrogram 130, Audio 108, Fixed labels 119, Editable labels 95 — every body is forced to 130. The regression tests state the two failures it fixes: without releasing the old fixed height the annotation chips came back as a 4 px sliver (tests/test_eventoverlay.py:975-999), and every group must end up at one height (tests/test_labels.py:691-705). Note the bar's HEIGHT constancy across tabs no longer depends on equalize — QStackedLayout reports the max over all pages (:2698-2702).

### Risks

- The tab strip is the hardest floor: 489 px minimum for five non-wrapping, left-packed QToolButtons (databrowser.py:461-468, 486-506). No side panel narrower than ~500 px can show the current horizontal strip. It must become a vertical strip, a two-row grid, a QComboBox page selector, or an accordion — and if it becomes a vertical QTabBar it will inherit the file-spine QTabBar styling that ParameterTabs was written to escape (databrowser.py:428-441).
- Nothing in the bar wraps. Every container field is a plain QHBoxLayout with a trailing stretch (annotation Source :5661, annotation Show :5676, annotation chip rows :5742, Editable Show :4602, Audio Pair :2623). At 300 px these clip rather than reflow: 696 px and 555 px of layer chips, 326 px of surface chips, 266 px of source line. A flow layout (or CategoryStrip's hand-packing generalised) is required for at least four rows.
- add_row's shape is label-left/field-right in one grid. In a 300 px panel a 114 px caption ('HIGH-PASS  H / ⇧H') eats 38% of the width. Either the caption moves above the field (doubling row height, which the panel can afford) or the shortcut is dropped from the caption — but the shortcut-in-the-caption is the bar's stated design rule (databrowser.py:2327-2333) and the tab tool tip is built from ParameterGroup.shortcuts (:509-515), so dropping it silently empties the tool tips.
- equalize() calls body.setFixedHeight(max totalSizeHint height) (databrowser.py:406). In a vertical panel every group should be free to be its natural height and to scroll; keeping equalize would pad every page to the tallest one and, worse, a fixed height plus rows that now WRAP means totalSizeHint must be re-measured at the panel's actual width — grid.totalSizeHint() is width-independent, so any height-for-width reflow will be mis-measured by equalize and clipped. equalize is arguably the first thing to delete in a side panel, but three call sites depend on it (:4684, :5839, :8416).
- LogSlider.setMinimumWidth(theme.AXIS_LEFT_WIDTH * 2) = 112 px (databrowser.py:598) leaves a 300 px panel with ~170 px for a caption and a SpinBox on the same row. Three sliders use it. Either the sliders get their own full-width row under their caption, or the 112 px floor has to be revisited — and it exists because slider width IS frequency resolution (:293-304).
- ColorMapCombo's 267 px minimum comes from a hard-coded 64×12 gradient icon (databrowser.py:623, 645). It cannot be narrowed without shrinking the swatch, which is the whole point of the widget.
- self.hetbuttonw is assigned ONLY inside `if self.data.rate > 50000` (databrowser.py:2685) and has no None default in __init__ (unlike audiofacw/audiosrcw/nfftw/... at :1317-1326). Any rebuild/teardown code the migration adds that touches self.hetbuttonw will raise AttributeError on recordings at or below 50 kHz.
- A QStackedLayout gives geometry only to the current page, so three widgets are stale until their tab is raised (databrowser.py:5977-6000: label_statusw elides, annotation_hoverw elides, label_chipbox folds). A side panel that is resizable by drag makes this worse — the repair currently hangs off sigTabChanged and off apply_resize (:6176-6186), and apply_resize only calls update_label_status(), NOT label_chipbox.relayout() or reelide_annotation_hover(); CategoryStrip saves itself via its own resizeEvent, but the annotation readout does not.
- The bar is per-browser (one DataBrowser per QTabWidget tab, databrowser.py:990, audian.py:1670) and every field is bound to one recording's nyquist and channel count. A QMainWindow-level QDockWidget would need a per-browser page stack swapped on tab change; an in-browser horizontal splitter avoids that but is not literally an Inkscape-style dock and cannot be torn off or shared across tabs.
- theme.band(self.parambar, top=True) (databrowser.py:2347) only offers top/bottom rules (theme.py:1593-1619). A right-hand panel needs a rule on its LEFT edge, which the theme helper cannot currently express; the BAND_PROPERTY string it stamps is also what restyle_tree replays on a theme switch, so a hand-written stylesheet would drop out of the live theme switch.
- The parambar is currently (Preferred, Fixed) vertically and ParameterTabs pins its own stack host for a documented reason (402 px of bar against a 154 px hint). Moving to a side panel inverts the constraint — the panel wants to be Fixed HORIZONTALLY and free vertically — and every one of those policy lines (:2352, :476-477) plus the tests that assert them (tests/test_parameterbar.py:230-233) has to flip together or the panel will eat the channel stack's width instead of its height.

### Risks

- WIDTH FLOOR IS THE REAL COST, AND IT IS ALREADY BINDING. The browser's minimum width IS the bar's minimum width today (517 empty, 793 with a session bundle loaded, measured). Stacked vertically that costs nothing extra because the splitter's own minimum width is only 110. Put side by side in a right dock, the two add: the floor becomes roughly 110 + dock_width + handle. With a bundle loaded that is ~910 px against today's 793, and the window floor (measured 797 with a bundle, 695 empty) rises with it. The bar cannot simply be rotated at its current minimum width.
- TODO.MD'S 734 PX CLAIM IS ONLY TRUE WITH NOTHING LOADED. Measured on Qt6: window floor 695 empty (StartupPage), but 797 once a bundle's ten layer chips are in the Fixed-labels group -- at which point the parameter bar, not StartupPage, is the binding term. Any width budget for the dock has to be set against 793, not 501.
- THE TAB STRIP IS THE SECOND WIDTH TERM AND IS HORIZONTAL BY CONSTRUCTION. ParameterTabs.strip is a QHBoxLayout of five QToolButtons whose minimum is 489 px (measured; buttons 64/117/63/108/129). A right dock narrower than ~500 px clips it. The tab strip must be re-oriented (vertical, wrapped, or a combo) -- and tests/test_parameterbar.py:88-97 pins 'the strip is not what sets the floor'.
- FOUR CONTROLS ARE MARKED 'WIDTH IS RESOLUTION'. hpsliderw, lpsliderw, ofracw and envsliderw are wrapped in ParameterGroup.expanding() precisely so they take the bar's full width; LogSlider's only guarantee is 112 px. In a ~300 px dock the filter and overlap sliders lose most of their travel. The stated design rationale at databrowser.py:251-260 has to be revisited, not just re-laid-out.
- TWO WIDGETS ELIDE TO THEIR OWN WIDTH AND ONE FOLDS. label_statusw and annotation_hoverw are QSizePolicy.Ignored and elide; label_chipbox (CategoryStrip) hand-places chips and folds the overflow into a +N menu. Its docstring records that it works today because the page gets 1167 px; in a narrow dock most categories fold and the digit-key chips stop being visible. Same for the annotation chip rows (ten chips = 1133 px, databrowser.py:143-152) -- and unlike CategoryStrip those are a real layout, so they would set a hard minimum width on the dock.
- ParameterGroup.equalize FORCES EVERY GROUP TO ONE FRAME HEIGHT (measured 130 px). That trade -- height is free, width is scarce -- is stated in three docstrings (databrowser.py:145-152, 4570-4584, labeloverlay.py:1267-1271) and inverts in a side panel, where height is what the panel has and width is what it lacks. equalize() and the three QTimer.singleShot(0, equalize_parameter_bar) calls (4684, 5839, 8417) become the wrong policy rather than merely mis-tuned.
- theme.band() CANNOT DRAW A LEADING VERTICAL RULE. Its signature is band(widget, top=False, bottom=False, ground=...) and it emits only border-top / border-bottom (theme.py:1593-1618). The bar's chrome seam at databrowser.py:2347 has no right-dock equivalent without extending band() -- and restyle_tree round-trips the BAND_PROPERTY string '{top}{bottom}|{ground}' (theme.py:1640-1650), so the property format changes too.
- A QDockWidget NEEDS A QMainWindow, AND THE ONLY ONE IS THE APPLICATION WINDOW. DataBrowser is a plain QWidget page inside Audian.tabs (audian.py:4959), and every open file has its OWN parameter bar. A window-level dock would have to swap contents on tab change (Audian.tabs.currentChanged -> adapt_menu, audian.py:1683 is the existing hook); the alternative is a horizontal QSplitter inside DataBrowser.vbox, which needs no QMainWindow and inherits the already-styled QSplitter::handle:horizontal (theme.py:2510-2513).
- THE LANE ENGINE WILL FOLLOW BY ITSELF, EXCEPT ON THE COLD PATH. lane_geometry reads stack_area.viewport().height() and so picks up the reclaimed 168 px automatically -- but its fallback branch uses the `height` argument, and all 11 adjust_layout call sites pass the browser's full height (databrowser.py:1811 etc.). With the bar beside the stack rather than under it that fallback stops over-counting by 168 px, which changes the first-pass lane height before the viewport is real. Worth an explicit check against show_focused_lane's measured table (databrowser.py:3088-3095).
- NINE TESTS PIN NUMBERS THAT THIS CHANGE MOVES. tests/test_panelsplitter.py:2443-2446 asserts 501 / 501+2*S8 / 695 exactly; tests/test_parameterbar.py:66-83 asserts bar == widest group + 2*S8, :88-97 the strip claim, :155-207 constant bar height with <=2 px scroll slack, :609-622 window floor < 1097 with all three bars under it. tests/test_annotationpanel.py:132 fabricates self.parambar = QWidget(self) and :528-535 asserts the bar's sizeHint width does not move -- a fake that will need to match whatever container replaces the bar.
- adjust_layout ALREADY USES self.width() FOR THE POWER COLUMN: figs[c].ci.layout.setColumnFixedWidth(1, 0.1*width) (databrowser.py:7225). A right dock narrows the lanes, so the power column and every width-derived plot metric shrink with it -- the horizontal cost is not confined to chrome.

## state-and-settings

The parameter bar is a per-DataBrowser widget (`self.parambar`, built in `setup_parameter_bar` at src/audian/databrowser.py:2326 and appended to the browser's own QVBoxLayout at :2063), so there is one bar per open file tab and src/audian/audian.py contains ZERO references to `parambar`, `param_tabs`, `param_groups`, `ParameterTabs` or `ParameterGroup` (verified by grep). Consequences: (1) NO QAction and NO keyboard shortcut anywhere shows, hides or switches a parameter tab — the only tab changes are a click on a tab button (ParameterTabs.add wires clicked→show_index, :483-508), `restore_parameter_tab()` once at build (:2710), and two deliberate programmatic raises: FIXED_TAB when a bundle finishes loading (:5831) and EDITABLE_TAB when label mode is entered (:8240, reached by the `b` key / toolbar Label mode). (2) There is NO action to hide or show the bar at all; nothing ever calls `parambar.setVisible` (all 34 `parambar` references are construction or parenting). (3) There is NO `link_*` switch and no `dispatch_*` for the tab: a second browser gets the same tab only because each new DataBrowser reads the settings file at build time; already-open browsers never follow.

Persistence: `PARAM_TAB_SETTING = "parameter-tab"` (:1041), `PARAM_TAB_SETTING_VERSION = 2` (:1045). Read path `parameter_tab_settings()` (:5843) returns `{}` plus a `log.warning` on a version mismatch. Apply path `restore_parameter_tab()` (:5861) resolves BY NAME with `show_index(0)` as fallback. `parameter_tab_changed()` (:5877), wired to `sigTabChanged` at :2360, saves and then repairs the three width-derived widgets. `save_parameter_tab()` (:5898) is NOT debounced — it is guarded only by the `_param_tab_saved` memo (:1461) and writes synchronously through `save_setting` (src/audian/audian.py:989), which is a whole-file read-modify-write; the sibling settings do use `QTimer.singleShot(0, …)` debounces (`schedule_annotation_save` :5349, `schedule_label_save` :3900, `schedule_spectrogram_save` :7038). The only timers touching the bar are three `QTimer.singleShot(0, self.equalize_parameter_bar)` calls (:4684, :5839, :8417).

Both label groups are built unconditionally: `setup_label_group` (:4567, EDITABLE_TAB, 3 rows + a span row) and `setup_annotation_group` (:5629, FIXED_TAB, 5 rows). Neither calls setVisible; the QStackedLayout owns visibility.

The single-visible-group invariant is load-bearing in four places: `ParameterGroup.equalize` freezes every group's body to the TALLEST group's height (:372-410); the bar's constant height and its 517 px minimum width both come from QStackedLayout reporting the MAX over pages plus an explicit `Fixed` vertical policy on `parambar` (:2352), on the stack host and on ParameterTabs itself (:471-473); `ParameterTabs.set_alert` (:542) exists solely to mark a tab whose HIDDEN page is saying READ-ONLY / SAVE FAILED / WRONG RECORDING; and `parameter_tab_changed` exists solely because a never-raised page has a stale 100 px width, which breaks the two eliding labels and the folding chip strip.

### Risks

- equalize() breaks outright if several groups are shown stacked: it calls body.setFixedHeight(max height) on every group (databrowser.py:372-410), so five groups in a panel would each be as tall as the Fixed-labels group's five rows -- roughly 5x130 px of frame where the natural heights sum to far less. Either equalize must become a no-op in panel mode (and the row-stretch-under-last-row packing at :407 must move into each group), or the panel must keep exactly one group visible.
- The Fixed vertical size policies (parambar :2352, ParameterTabs host and self :471-473) exist because QStackedLayout inherits expandingDirections() in both directions; measured without them the bar took 402 px against a 154 px hint and the stack's scroll viewport fell to 247 px over 616 px of content. In a vertical side panel the same policies would pin the panel to the SUM of every group's height with no way to scroll -- the panel needs its own QScrollArea, and the Fixed policy has to be re-reasoned rather than copied.
- Width inverts. Today the bar's minimum is the widest group + 2*S8 = 517 px, borrowed from the full window width; the window floor is 695 px (tests/test_panelsplitter.py:2443-2445). A right-hand panel takes that ~500 px permanently out of the lanes' width, and if narrowed below it the Spectrogram group's spin boxes and the Overlap slider have no room. The 168 px of height bought back is paid for in width unless the panel is collapsible.
- CategoryStrip folds everything into the +N menu at panel widths. Its minimumSizeHint is the +N button alone (labeloverlay.py:1317-1322) and relayout packs a prefix of the vocabulary against self.width() (:1382-1430); the strip currently gets 1167 px and fits twelve categories. At ~400 px most categories disappear into a menu, and the chips are the legend as well as the picker -- 'which colour means which word is read off the bar rather than remembered' (databrowser.py:4663-4666).
- The two Ignored-policy eliding labels degrade to near-nothing. annotation_hoverw carries a ~227-character line and was given a whole row precisely to get 1097 px (databrowser.py:5711-5723); label_statusw carries READ-ONLY / SAVE FAILED text. In a ~400 px panel both elide to a few words, and the alert '!' that compensated for a hidden page (ParameterTabs.set_alert :542) has no tab to sit on if the strip goes away. update_label_alert (:5942) and update_annotation_alert (:5956) both early-return on param_tabs is None, so dropping the strip silently disables both warnings rather than erroring.
- parameter_tab_changed (:5877) is the only thing that repairs the stale 100 px width of a never-raised page; if the panel drops the QStackedLayout, that signal stops firing and the three width-derived widgets are then repaired only by apply_resize (:6176). Conversely if the panel keeps a stack, every one of those calls must be preserved.
- raise_parameter_tab's two callers are deliberate attention moves -- a loaded bundle (:5831) and entering label mode (:8240) -- and both become no-ops if every group is visible. A panel needs an equivalent (scroll-to / expand-and-highlight) or those two affordances are lost silently, since raise_parameter_tab already swallows a missing strip (:5919-5922).
- The bar is per-DataBrowser, not per-window (one parambar per open file tab, databrowser.py:2062-2063), and audian.py never references it. Hoisting it to a single main-window dock would be a real ownership change: every widget is parented to self.parambar and wired to that browser's slots, so a shared panel needs a re-target-on-tab-change path modelled on sync_toolbar (audian.py:2817) / sync_annotation_actions (:4425), including the 'a background tab must not move the front tab's controls' guard.
- PARAM_TAB_SETTING's documentation comment (databrowser.py:1022-1027) is physically attached to FIXED_TAB (:1038), 14 lines above the constant it describes -- so anyone reading FIXED_TAB gets the wrong docstring and anyone reading PARAM_TAB_SETTING gets none. Any panel work that touches these constants should re-seat that block.
- Both label-group docstrings claim the group is 'hidden until a file is open' / 'hidden while no table is loaded' (databrowser.py:4595, :5633), but neither calls setVisible and both closing comments say the stack owns visibility (:4653-4657, :5764-5769). The prose is stale; a panel implementation that trusts it would add hiding behaviour the current design explicitly rejected ('a control that appears and disappears is one nobody learns to look at').
- save_parameter_tab has no debounce, only the _param_tab_saved memo (:5906). If a panel introduces any way for the current group to change repeatedly during a gesture -- scroll-spy on a scrolling panel, an accordion that opens on hover, a resize that re-raises a group -- each change becomes a full read-modify-write of settings.json. Such a design must add a schedule_* debounce on the pattern of schedule_annotation_save (:5349).
- A vertical tab strip on the right edge would re-enter the exact styling trap ParameterTabs was written to avoid: theme's stylesheet styles QTabBar with unconditional type selectors written for the left-edge file spine, including a selected mark that is a rule down the LEFT side (databrowser.py:428-436). Any new strip must stay QToolButton-based or the file spine's styling has to be re-scoped first.
- No shortcut currently shows, hides or switches anything about the bar, so a panel toggle is new surface. F10, F11 and F12 are the only unclaimed function keys (F2-F9 and Shift/Alt variants are all bound, audian.py:4639-4693 and databrowser.py:2229). Follow toggle_rail's rule (:2965-2984): a key that changes nothing visible must say so.

## tests

The parameter-bar test surface is 26 collected tests in tests/test_parameterbar.py (25 `def test_` functions; `test_a_tab_change_never_takes_height_from_the_channel_stack` is parametrized over two fixtures) plus 6 tests in 3 other modules that touch `parambar` / `param_tabs` / `ParameterGroup`, plus 1 stub in tests/test_annotationpanel.py that fakes the bar. Full suite: `.venv-qt6/bin/python -m pytest tests/ -q` — 864 tests collected (tests/test_parameterbar.py alone: 26).

Of the 25 functions in tests/test_parameterbar.py, only 15 are about the bar at all; tests/test_parameterbar.py:405-622 is a "chrome" section about the tool bar and status bar that a dock move does not touch except for the final `parambar.minimumSizeHint().width() < floor` assertion at tests/test_parameterbar.py:622. The load-bearing constraints for a move are: (1) the bar's minimum width must equal the widest group + 2*theme.S8 (tests/test_parameterbar.py:83, tests/test_parameterbar.py:117) and the window floor must stay under 1097 px (tests/test_parameterbar.py:618); (2) `parambar` and `param_tabs` must both keep `QSizePolicy.Policy.Fixed` **vertically** (tests/test_parameterbar.py:213) and `bar.height() == bar.sizeHint().height()` across every tab (tests/test_parameterbar.py:176,184) — in a right-hand dock the constrained axis inverts, so these two are the assertions that will fail by construction; (3) tests/test_panelsplitter.py:2443-2446 hard-codes three absolute pixels — Spectrogram group 501, bar 501+2*S8, window floor 695 — and any change to the bar's container or margins re-baselines it; (4) the `stack_area` vertical scroll-range assertion (tests/test_parameterbar.py:204) measures the bar's effect on the channel stack and is exactly the number a dock move is meant to improve.

Fixture pattern for a new dock test: import `app`, `open_stack`, `pump`, `settle` from tests/test_panelsplitter.py (tests/test_parameterbar.py:40-41), then `yield from open_stack(app, tmp_path_factory.mktemp("name"), channels)` in a module-scoped fixture (tests/test_parameterbar.py:48-57). `open_stack` (tests/test_panelsplitter.py:135-158) sandboxes settings, builds a real `audian_app.Audian` window at 1200x900, calls `set_panels(specs=1)`, and tears the window down inside the still-running event loop.

A new dock test must therefore reuse an existing module's browser fixture (add tests to tests/test_parameterbar.py) rather than opening a new module with its own windows; tests/test_panelsplitter.py:2072-2090 and tests/test_settings.py:14-17 both record that decision being taken deliberately.

### Risks

- HARD BLOCKER: tests/test_parameterbar.py:210-213 asserts `parambar` AND `param_tabs` are `QSizePolicy.Policy.Fixed` VERTICALLY. A right-hand dock inverts the constrained axis (Fixed horizontally, expanding vertically). This test cannot pass unmodified and must be rewritten as part of the move, not after it.
- HARD BLOCKER: tests/test_parameterbar.py:276 asserts `page.width() > 600` for the Audio group. Any dock narrower than 600 px fails outright. The same 600 px is the implicit premise of tests/test_parameterbar.py:277-278 (`audiosrcw.width() < page.width()/2`).
- EXACT-PIXEL RE-BASELINE: tests/test_panelsplitter.py:2443-2446 asserts three absolute equalities (501 / 501+2*S8 / 695). Changing the bar's parent, container margins, or the window's layout re-baselines all three, and the docstring shows this file has already been re-baselined once for Qt6. Plan to update it in the same commit and record the new measurements in its docstring, which is this repo's convention.
- SILENT-PASS RISK: tests/test_parameterbar.py:158-207 (the height test, 2 of 26 collected) becomes trivially true in a right-hand dock — the bar's height would no longer be the quantity under test. It would go green while measuring nothing, which is exactly the failure mode its own docstring warns about for `isVisible()` assertions. It needs to be re-pointed at the dock's WIDTH and at `stack_area`'s horizontal budget, or it is dead weight that hides a regression.
- WINDOW-FLOOR INVERSION: tests/test_parameterbar.py:618 requires `window.minimumSizeHint().width() < 1097`, and :120 requires `window.minimumSizeHint().width() > parambar minimum`. Stacked under the channel stack, the bar's width OVERLAPS the window's; docked at the right it ADDS to it. Unless the dock is collapsible or given a small horizontal minimum, the 1097 px laptop guarantee — the number the whole file exists to defend — is at risk, and the win would be vertical estate paid for in horizontal estate.
- NEW-MODULE SEGFAULT: adding a new test module with its own browser fixture costs two more top-level windows and reproduced a SIGSEGV in 2 runs of 4 inside `theme.collect_orphan_widgets` (todo.md:79-97), once while building test_parameterbar's own fixture. Add dock tests to tests/test_parameterbar.py reusing `browser`/`wide_browser`; do not create tests/test_paramdock.py. If a new module is unavoidable, fix `collect_orphan_widgets` (src/audian/theme.py:2026-2055) into a two-pass read-then-reparent with a validity check first, as its own commit.
- STUB COUPLING: tests/test_annotationpanel.py:130-133 hand-builds `parambar = QWidget(self)` with `param_tabs = None` and calls `setup_annotation_group()` outside `setup_parameter_bar`. If the dock refactor moves group construction into a dock class or makes it depend on a live tab strip, that ~1169-line module breaks wholesale, as does tests/test_annotationpanel.py:1110 which constructs `ParameterGroup('Reference', panel.parambar)`.
- NARROW-PAGE CONTENT REGRESSIONS invisible to the geometry tests: three widgets size off their own width() (label file row, annotation pointer readout, category chip strip). tests/test_parameterbar.py:237-238 asserts the label status line is NOT elided and tests/test_labels.py:722-770 asserts the chip strip folds to a prefix. Today a raised page gets ~1162 px; a right-hand dock gives far less, so these will fail on content even if every layout assertion passes. tests/test_annotationpanel.py:1122-1165 (`test_the_pointer_readout_is_wide_enough_to_reach_its_counts`) makes the same demand at a 960 px group width.
- GROUP-EQUALIZATION RATIONALE EVAPORATES: `ParameterGroup.equalize` gives every group the tallest one's frame (src/audian/databrowser.py:372), asserted at tests/test_labels.py:704 and tests/test_eventoverlay.py:997-999. In a bottom bar that costs lane height and is why the five-row ceiling exists (tests/test_annotationpanel.py:1092). In a tall dock, equalizing to the tallest wastes vertical space with no compensating reason, and the five-row ceiling becomes arbitrary — a design decision the tests will not flag either way.
- ACTION INVENTORY: if the move adds an action (show/hide the dock, focus it), tests/data/action-inventory.json must be regenerated in the same commit with AUDIAN_REGENERATE_GOLDEN=1 and the new key must not collide (tests/test_actioninventory.py:262-272). The sweep at tests/test_actioninventory.py:198 will also trigger the new action blind and must not open a modal or it needs an UNSWEEPABLE entry.
- STYLING: `theme.band(self.parambar, top=True)` (src/audian/databrowser.py:2347) draws the separating rule on the top edge, and objectName 'audianParamBar' is the QSS hook. A right-hand dock needs the rule on its leading (left) edge; no test asserts this, so it will regress silently and only be visible in the running app.
- The `settle()` + `pump()` discipline is load-bearing and unenforced: every geometry read in these files is preceded by an explicit settle/pump because Qt re-activates layouts before the next paint. A new dock test that reads geometry without them reads the frame before the one it means, and will be flaky rather than failing.
